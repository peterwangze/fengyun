# 3.6.0 三路同行验收

[跨区支线设计](../../../CORRIDOR_DESIGN.md)覆盖七个回访区。新增青石转运集、榆汊中渡两个可步行探索的聚落。三条支线各有两种走法，具体交接对象、去程和返程受选择影响。终战前交付的结果写入凤溪尾声，终战后可补交、探访接手人并领取或登记回单。

## 四条新档路线

| 路线 | 雄霸开场 | 潮关结案及回访 |
| --- | --- | --- |
| [截势](campaign-interrupt.log) | 木楔送竹井、明灯送苇津、拆闸上飞栈。合计开场 4 格合击，含旧主线支援。 | 州府会验。往返榆汊查粮仓公开船账，试挑担台，去飞栈找罗七，三线收单。 |
| [守反](campaign-retaliate.log) | 铁箍交东哨、遮舱走芦堤、架担入避险屋。雄霸开场 4 格势，含旧支线削势。步惊云和聂风均有护持。 | 公开分粮。找潮沟接手人核封签，拿东哨旧箍，查避险屋换药单，三线收单。 |
| [乘隙](campaign-exploit.log) | 铁箍交东哨，拆闸上飞栈。暂缓递船，开战只得到已完成两线的支援。 | 州府会验。结案后才走芦堤交药，再回潮沟收单。凤溪尾声仍按终战当天的交付记录演出。 |
| [无采购](campaign-standard.log) | 保持原主线开场效果，可直接攀登祭台。 | 公开分粮，完成原有覆核、分粮与凤溪回航，不接三条新线仍可通关。 |

四条均使用独立新档，从正常标题进入，由脚本输入方向、调查、选择与战斗指令。三套配装在实际战斗中分别触发截势 18 次、守反 27 次、乘隙 6 次。三条配装路线都在同一档并行接单，检查驿路手记标出实际可用船道，结案后拿齐三类回执。 [简单难度补跑](campaign-easy.log)

## 双平台安装

Windows 11 x64 和 Android 16 模拟器均用实际 3.6.0 安装包覆盖公开版 3.5.0，验证旧档、七区舆图、北槽接单、驿路手记和重启续玩。Windows 安装器未获 Authenticode 签名。APK 使用原发行签名。 [Windows 验收](windows-360-result.json) · [Android 验收](android-360.log) · [SHA-256](SHA256SUMS.txt)

## 复跑

按[全战役运行参数](../full-campaign/README.md#复跑)为每条路线追加 `--corridors`，并用不同的 `qa_` 存档名。日志中的 `CORRIDORS`、`PASS Tidegate` 和 `RESULT` 记录实际援助、结案及回访。专项脚本的参数见上方各支线记录。
